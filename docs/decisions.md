## 2026-10-31 S2.4: reader, execution, lifecycle, preflight

- **Stop path (A7.5).** `runManagedTurn` snapshots the owned descendants, SIGTERMs the child's process group, then SIGKILLs every identified row after `GRACE_MS` (3 s, bounded by the retry interval; `taskkill /T /F` on Windows). The donor stopped by SIGKILL at once; the extra SIGTERM pass adds one process snapshot before the kills, which the heartbeat test records.
- **Post-exit cleanup budget.** The post-exit scan uses the whole shutdown budget (GROKX `lifecycle.mjs`), not one query's (CODEXCC); CODEXCC contributes `PIPE_WAIT_MS` (12 s), the unattributed-pipe handling and `thread locked`.
- **Held output (A7.8).** A clean exit whose pipes stay open past `PIPE_WAIT_MS` marks the job `threadLocked`, keeps its claim and fails with the `thread locked` hint; plain `cancel` refuses to release it even with the owner gone; `cancel --confirm-ended` releases only when the process table shows no owner companion and no owned row, and refuses with exit 10 on a live owner, a live owned child or a failed query.
- **afterTurn placement.** `adapter.afterTurn(ctx, outcome)` runs once after cleanup is verified (or after the failure/cancellation is settled), before the outcome is mapped, so a Gemini snapshot can contribute `edited`, `failedCommands` or `incomplete`.
- **Preflight cache.** `exec`/`network` descriptors are the cached cold probes (keyed by executable path, size, mtime and the descriptor set); `dir`/`file`/`listener`/`process-table` descriptors describe the sandbox in effect and are re-checked on every call. A blocked descriptor stops the run before any later probe and caches nothing.
- **Reader thread check.** The generic reader fails the turn when an event names a thread other than the expected one (the Grok session-confirmation rule, now adapter-neutral); a missing id leaves the thread unconfirmed.
- **Entry-driven cases deferred to S2.6.** `wait --timeout` → 20, subprocess counters for cold/warm/replay/owner-death, depth guard and `--deadline`/`--inactivity-timeout` through argv, and the fake PowerShell runner's self-identity ticks run through `main()` once the entry exists; S2.4 tests them at module level (`depthGuard`, `companionState` ticks, `options.deadlineMs`/`inactivityMs`).

## 2026-10-31 S2.6: entry wiring

- **Order (A4, S2.6).** `main()` parses argv and `--cwd`, reads the text (no stdin for control verbs, bare `review` and `--next-input`), applies the guards (five depth variables → exit 1; a state root inside realpath(cwd) → exit 1), looks the request id up and replays before any selector, catalog, adapter or preflight, then resolves the provider (`--to`, or the job or thread record; a conflicting `--to` → 2; an ambiguous bare id → 2), imports `./lib/providers/<p>.mjs` (absent → 2 `provider <p> not available in this build`), resolves tier, model and effort, runs the cached preflight, claims the request id, and runs the managed turn. Text is read in step (1) because the fingerprint (step 3) covers it.
- **The workspace is realpath(cwd)** for the state-root guard and for `--last`/bare `wait`/bare `cancel` (A7.1, A7.2); the Git root is resolved only by reviews.
- **Native thread ids must be known to council** (a job or a thread record) before `reply` or `task --thread` resumes them; GROKX accepted any UUID. A7.3 forbids adopting a native thread across workspaces, and an unrecorded id carries no workspace to check. A known thread always continues in its recorded cwd; a missing one exits 2.
- **Preflight order.** Sandbox descriptors (`dir`, `file`, `listener`, `process-table`) run before the cached probes (`exec`, `network`), so a blocked resource exits 1 with zero probes as well as zero submissions.
- **Request claim after preflight.** A fresh request id is claimed after preflight, immediately before admission; a blocked preflight or a usage error leaves no reservation. A turn refused before preparing (a busy thread) releases its reservation, so the id may run again (A7.4: "a claim that fails before preparation completes is released"); a turn that prepared keeps its tombstone and replays its outcome, failure or cancellation included. An abandoned reservation (companion gone, nothing prepared) is released by the replaying call, which exits 2 telling the caller the same id can run again.
- **The fingerprint includes `--deadline` and `--inactivity-timeout`** (as CLAUDEX: "a changed deadline still conflicts") and excludes `--json`, `--request-id` and `--timeout`.
- **Adapter calls the entry makes**: `buildTurn(request)` receives `{verb, text, prompt, instructions, contractPath, model, effort, resume, threadId, cwd, env, schemaPath, structured, readOnly, web, allowCommands, maxTurns, maxBudgetUsd, policy, agent, jobDir}`; the entry adds the five guard variables to whatever environment the adapter returns. `finalizeReview` returns the schema-shaped object (or `{structured}`); the core validates, reconciles the ledger and publishes coverage (`finalizeReviewTurn`). `reviewPlan(review, {adversarial})` picks the schema carrier (`embed` makes the batch prompt carry the schema text). `probe(launcher)` is run fresh by `setup` and by `models --refresh`.
- **Defaults.** Tier `consult` for ask/review/reply on a new thread, `exec` for task (GROKX `rescue`); a reply or `task --thread` inherits model, effort and tier unless `--tier`, `--model` or `--effort` is given, and an explicit value persists. Timeouts from GROKX: inactivity 1200 s, deadline 14400 s, `wait` 90 s, `cancel` 30 s; rounds 9 unless `--rounds` or `COUNCIL_CODEX_ROUNDS`.
- **Footer.** `batch i/n` is printed only when a review has more than one batch; `unreviewed N` counts unsupported input only (pending saved batches are `pending`, A5.2).
- **macOS ownership.** Where the process table gives only text (macOS `ps`), a row is owned only when it ends with the job's complete recorded child arguments and its program is the recorded launcher or the same native binary (GROKX's rule, generalized); the adapter's `ownsProcess` decides for argument vectors (Linux, Windows). The darwin group rule follows only groups an owned row leads (the lifecycle spawns the child detached): an earlier draft that followed any owned row's group killed the test runner's own process group during S2.6 development, and the regression test now pins the rule.
- **Test seams.** `main(argv, env, io, deps)` accepts `deps.platform`, `deps.powershell`, `deps.snapshot`, `deps.cwd` and lifecycle `deps.hooks` for in-process tests (fake PowerShell self-identity, held-output lock); the command line passes none. The null adapter is importable only under `COUNCIL_TEST_NULL_ADAPTER=1` from the repository's `tests/fixtures/`.
- **Entry-driven S2.4 cases landed here**: `wait --timeout` → 20, `--deadline`/`--inactivity-timeout` through argv, the depth guard through argv for all five variables, the state-root guard, subprocess counters (cold 1 probe + 1 submission, warm 0 probes, replay 0 processes, owner-death cancel 0 provider processes), and the fake-PowerShell self-identity cases through `main()` (`tests/cli-smoke`, `core-recovery`, `core-requests`, `core-windows`, `core-locks`, `core-setup`, `core-entry`, `core-review-entry`, `core-cancel`, `core-lifecycle-integration`).
