## 2026-10-31 S2.6: entry wiring

- **Order (A4, S2.6).** `main()` parses argv and `--cwd`, reads the text (no stdin for control verbs, bare `review` and `--next-input`), applies the guards (five depth variables → exit 1; a state root inside realpath(cwd) → exit 1), looks the request id up and replays before any selector, catalog, adapter or preflight, then resolves the provider (`--to`, or the job or thread record; a conflicting `--to` → 2; an ambiguous bare id → 2), imports `./lib/providers/<p>.mjs` (absent → 2 `provider <p> not available in this build`), resolves tier, model and effort, runs the cached preflight, claims the request id, and runs the managed turn. Text is read in step (1) because the fingerprint (step 3) covers it.
- **The workspace is realpath(cwd)** for the state-root guard and for `--last`/bare `wait`/bare `cancel` (A7.1, A7.2); the Git root is resolved only by reviews.
- **Native thread ids must be known to council** (a job or a thread record) before `reply` or `task --thread` resumes them; GROKX accepted any UUID. A7.3 forbids adopting a native thread across workspaces, and an unrecorded id carries no workspace to check. A known thread always continues in its recorded cwd; a missing one exits 2.
- **Preflight order.** Sandbox descriptors (`dir`, `file`, `listener`, `process-table`) run before the cached probes (`exec`, `network`), so a blocked resource exits 1 with zero probes as well as zero submissions.
- **Request claim after preflight.** A fresh request id is claimed after preflight, immediately before admission; a blocked preflight or a usage error leaves no reservation. A turn refused before preparing (a busy thread) releases its reservation, so the id may run again (A7.4: "a claim that fails before preparation completes is released"); a turn that prepared keeps its tombstone and replays its outcome, failure or cancellation included. An abandoned reservation (companion gone, nothing prepared) is released by the replaying call, which exits 2 telling the caller the same id can run again.
- **The fingerprint includes `--deadline` and `--inactivity-timeout`** (as CLAUDEX: "a changed deadline still conflicts") and excludes `--json`, `--request-id` and `--timeout`. *Superseded at S2.8 (F19): both timers are excluded, as on the twin.*
- **Adapter calls the entry makes**: `buildTurn(request)` receives `{verb, text, prompt, instructions, contractPath, model, effort, resume, threadId, cwd, env, schemaPath, structured, readOnly, web, allowCommands, maxTurns, maxBudgetUsd, policy, agent, jobDir}`; the entry adds the five guard variables to whatever environment the adapter returns. `finalizeReview` returns the schema-shaped object (or `{structured}`); the core validates, reconciles the ledger and publishes coverage (`finalizeReviewTurn`). `reviewPlan(review, {adversarial})` picks the schema carrier (`embed` makes the batch prompt carry the schema text). `probe(launcher)` is run fresh by `setup` and by `models --refresh`.

Timeouts from GROKX: inactivity 1200 s, deadline 14400 s, `wait` 90 s, `cancel` 30 s; rounds 9 unless `--rounds` or `COUNCIL_CODEX_ROUNDS`.
- **Footer.** `batch i/n` is printed only when a review has more than one batch; `unreviewed N` counts unsupported input only (pending saved batches are `pending`, A5.2).
- **macOS ownership.** Where the process table gives only text (macOS `ps`), a row is owned only when it ends with the job's complete recorded child arguments and its program is the recorded launcher or the same native binary (GROKX's rule, generalized); the adapter's `ownsProcess` decides for argument vectors (Linux, Windows).
