# Spike record: agy (Antigravity CLI, Gemini)

Recorded 2026-10-31 on macOS (arm64), Node 22.19.0, by the S1.2 probes. Sanitized streams: `tests/fixtures/streams/agy.json`. Every live probe ran once at `--effort low` (or the effort the matrix names) on a scratch Git repository; models `gemini-4-argon` (ask, resume) and `gemini-3.8-flash` (the rest). Paid turns: 13 (ask, resume, 2 effort successes, web ×2, denial, allow-pair ×2, review, cancel, print-timeout); the 3 effort errors exited before any model call. agy reports no cost.

## Version and launcher

`agy --version` → `1.4.12`; PATH `/Users/cia/.local/bin/agy`. `agy --help` captured as `docs/spike/agy-help.txt`: `--effort` is documented as `low|medium|high|xhigh|max` but the models offer only low/medium/high (Effort rules); `--input-format stream-json` implies print mode; `--print-timeout <n>s`; `--json-schema` string or path; `--settings` inline or path; `--mode accept-edits|auto|plan`; `--sandbox`; `--add-dir`; `--dangerously-skip-permissions` (never used).

## Headless invocation (exact argv)

```
agy --input-format stream-json --output-format stream-json --disable-slash-commands --print-timeout 120s --sandbox \
  --settings <job>/settings.json --model gemini-4-argon --effort low [--conversation <id>] [--json-schema <path>] [--mode accept-edits]
```

Read-only settings file used: `{"permissions":{"allow":[],"ask":[],"deny":["write_file(*)","edit_file(*)","command(*)","unsandboxed(*)","mcp(*)","execute_url(*)"]},"agentMode":"","toolPermission":"request-review"}`. Exit 0 on SUCCESS and on `print_timeout`; 1 on `status: "ERROR"` results and after SIGTERM.

## Stdin shape

One NDJSON line then EOF, as AGYX `native.mjs` writes it: `{"event":"user","message":{"content":"<prompt>"}}`.

## Event names seen

`init` (`conversation_id` generated by agy, `init.cwd`, `init.tools` (60 names incl. `write_file`, `edit_file`, `run_command`, `search_web`, `call_mcp_tool`), `init.permission_mode` = the session file's `toolPermission`: `request-review`, or `always-proceed` when the file says so); `step_update` with `step_type` `user_input`, `system_message` (resume), `agent_response` (`text_delta`, `usage` on DONE), `tool` (`tool_name`, `tool_info.parameters`, `tool_info.output`, `tool_info.error {type: "TOOL_ERROR", message}`, states ACTIVE/DONE/ERROR); `result` (`conversation_id`, `status` SUCCESS|ERROR, `response`, `duration_seconds`, `num_turns`, `usage`, optional `finished_reason`, `denied_actions`, `structured_output`, `json_schema`, `error`).

## Resume form

`--conversation <id>` with the id from `init`/`result`; `num_turns: 2`, a `system_message` step precedes the answer; the model remembered the first turn ("pong2").

## Read-only controls and their evidence

- Deny-rule denial (read-only file above): asked to create a file and run `which node`, agy emitted `step_update` `tool` state `ERROR` for `write_file` and for `run_command` with `tool_info.error.message` "permission check failed for … Permission denied for … Matches user-configured deny rule."; `result.status: "SUCCESS"`, `response` is the model's report, no `denied_actions` field; no file appeared. This is the A2 regex signature.
- The global `~/.gemini/antigravity-cli/settings.json` holds `allow: ["command(which)", …]` and `toolPermission: "always-proceed"` and no `deny` array. With the session file above, `which node` was denied and `init.permission_mode` read `request-review`: the session file's lists and `toolPermission` replace the global ones, as A5.1 says `sessionSettings` must therefore merge the global lists first. The plan's "global `allow: ["run_command(*)"]`" variant was not run (it would have edited the user's settings file); the existing `command(which)` allow served the same purpose.
- Prompt-style denial under `toolPermission: "request-review"`, `--mode accept-edits`, allow `command(node check.mjs)`/`unsandboxed(node check.mjs)`: `node check.mjs` ran (`output: "Command exited with code 0 … check ok"`); `node other.mjs` → tool step `ERROR` "permission check failed for command "node other.mjs": user denied permission to run command …" and `result.denied_actions: [{"action":"command","display_name":"RunCommand"}]`, `response: ""`, `status: "SUCCESS"`, stderr `jetski: no output produced — a tool required the "command" permission that headless mode cannot prompt for, so it was auto-denied…`. So `denied_actions` does exist (A2 corrected): the adapter honours both signatures.
- The same allow pair under `toolPermission: "always-proceed"` (the user's global value, which AGYX `sessionSettings` keeps on edit turns) ran `node other.mjs` too: the allow pair restricts nothing unless `toolPermission` is `strict` or `request-review` (decisions.md; S5.2 question).
- `--json-schema <path>` with the S1.0 schema: the model called `finish`; `result.structured_output` holds the object, `result.json_schema` echoes the schema, `response` holds the JSON string. Findings carried `id` and `decision`.

## Web tool and decision rule

A read-only turn asked to search the web used tool `search_web` (step `tool`, DONE). With `search_web(*)` added to the deny list the search still succeeded. Per A3.3: read-only Gemini turns cannot deny web search, so Gemini `--web` exits 2 and `setup` lists "web search cannot be switched off on Gemini" as a trade-off (decisions.md).

## Process table incl. pgid

`agy --input-format … --settings <path> …` visible with the `--settings` operand (ownership evidence); pid 61829, pgid 61829 (detached spawn). ## Cancel behaviour

`kill -TERM -- -<pgid>` 5.3 s after start: exit code 1 after 115 ms, stderr `error: interrupted`, and a final `result` with `status: "ERROR"`, `error: "interrupted"`, `finished_reason: "interrupted"`; no survivors; pipes closed with the process.

## Timeouts

`--print-timeout 5s` on a long prompt: exit 0, `result.status: "SUCCESS"`, `response: ""`, `finished_reason: "print_timeout"`, stderr `[agy] print timeout after 5s with turn in progress; returning partial output` (A2 confirmed; council exits 1).

Not available; A8 (Gemini on Windows qualified in S7.2 or reported unsupported).

## Surprises

- `denied_actions` exists on prompt-style denials (request-review); A2 said native results have none. Both signatures recorded above.
- `--allow-command` restricts nothing under the user's global `toolPermission: "always-proceed"`.
- The `search_web(*)` deny rule does not block web search.
- Cancel yields a terminal `result` with `status: "ERROR"` and `finished_reason: "interrupted"`, so a reader must not treat every `result` as completion.
- `--effort` help lists `xhigh|max` that no Gemini model accepts.
